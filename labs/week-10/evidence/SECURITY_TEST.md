## ผลการทดสอบ SQL Injection

### ① เงื่อนไขที่เป็นจริงเสมอ

**ยิง** `GET /api/requests?status=x' OR '1'='1`
**ผลที่ได้** `[]` (0 รายการ) ✓ ถูกป้องกัน
**เพราะ** ใช้ parameterized query — ค่าถูกตีความเป็นข้อความ ไม่ใช่คำสั่ง

---

### ② พยายามลบตาราง
**ยิง** `GET /api/requests?status='; DROP TABLE requests; --`
**ผลที่ได้** `[]` (0 รายการ) ✓ ตาราง requests ยังอยู่
**เพราะ** ค่าพารามิเตอร์ถูก escape และส่งเป็น value แยกต่างหาก คำสั่งซ้อน (Stacked Query) จึงไม่ถูกประมวลผล ตาราง `requests` ไม่ถูกลบและดึงข้อมูลต่อได้ปกติ

---

### ③ ต่อเงื่อนไขเพิ่ม
**ยิง** `GET /api/requests?status=pending' OR status='completed`
**ผลที่ได้** `[]` (0 รายการ) ✓ ถูกป้องกัน
**เพราะ** ระบบค้นหาสถานะที่ตรงกับข้อความ `"pending' OR status='completed"` ทั้งก้อน ไม่ได้แตกเป็นเงื่อนไข OR ในประโยคคำสั่ง

---

### ⑤ สิ่งที่ Parameterized Query (?) ใช้แทนไม่ได้

เครื่องหมาย `?` ใช้ได้เฉพาะแทนที่ **ค่าข้อมูล (Literals)** เท่านั้น ไม่สามารถนำมาใช้แทนชื่อตาราง หรือชื่อคอลัมน์ในคำสั่ง SQL ได้ เช่น:

```javascript
// ❌ ใช้งานไม่ได้ — เครื่องหมาย ? แทนชื่อคอลัมน์ไม่ได้ จะเกิด Syntax Error หรือเรียงลำดับผิดพลาด
db.prepare('SELECT * FROM requests ORDER BY ?').all(sortBy);
